<objective>
Record every authorization denial as a rate-bounded security event (D-11-05): 401/403 from the consolidated gate and
the deal resolver, and every clearance-404, each with actor, canonical route, method and reason — at most one audit
row per actor+route+reason per 60 s, with the folded denials counted, so a probe cannot flood the append-only audit.db.

Purpose: AUTHZ-05 — no denial is logged today (PRD Problem); audit.db is append-only and amplification-prone
(R1-07/R2-01), so the trail must stay proportional.
Output: lib/denialAudit.js, gate/resolver/404 wiring, tests; denial-triggering suites isolated to temp audit files.

Adaptation of D-11-05 recorded for the checker: the PRD wording "an incrementing counter in the same row's detail"
cannot be implemented literally — db/audit-schema.sql has `audit_log_no_update` / `audit_log_no_delete` triggers that
RAISE(ABORT) on any UPDATE (AUD-02), which the PRD itself cites ("audit.db is append-only"). The counter therefore
lives in memory per window and is written as the window's `count` — the first denial writes the window's row
immediately (count 1), and the denials folded into an expired window are written once as that key's next row
(`count = n`, `folded: true`), keeping the ≤ 1 row / 60 s bound and losing no count across a running process. This
preserves both the rate bound and the counter without touching the append-only invariant.

server.js regions owned by this plan in W2 (parallel with 11-05 and 11-06, provably disjoint): the consolidated gate
body (~746-846, refusal lines only), `GET /api/deals/:id/grants` inline 403 (~1739-1741) and the RecordNotFoundError
error-middleware branch added by 11-03 (~7865). One require line is added directly after the `readPolicy` require
added by 11-01.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-30 | Denial of Service | audit flooding by probes | high | mitigate | ≤ 1 row per actor+method+route-template+reason per 60 s; ids collapse into templates; capped key map with overflow folding |
| T-11-31 | Repudiation | denials unrecorded | medium | mitigate | every gate/resolver 401/403 and clearance-404 recorded; folded counts written, never dropped while the process runs |
| T-11-32 | Denial of Service | memory growth of the window map | medium | mitigate | maxKeys cap (5000), idle-key eviction in sweep, unref'd interval |
| T-11-33 | Tampering | audit row mutation to keep a counter | high | mitigate | no UPDATE statement in lib/denialAudit.js code lines (grep gate); AUD-02 triggers untouched |
| T-11-34 | Information Disclosure | audit rows carrying request bodies or secrets | low | mitigate | rows carry route template, canonical path, method, reason, counts and requestMeta only — never bodies |
| T-11-35 | Repudiation | multi-process deployments multiply the bound | low | accept | the bound is per process; Option B runs a small fixed process count (replicas:1), so the multiplier is the process count — documented in DEPLOYMENT.md by plan 11-08 |
| T-11-36 | Denial of Service | busy audit append on a denial | low | accept | Phase 8 no-swallow contract: a refusal that cannot be audited is still refused (503); never converted into a success |
