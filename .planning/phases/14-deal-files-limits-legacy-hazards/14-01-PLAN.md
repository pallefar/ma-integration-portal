## Planner decisions (this plan)
- **PD-1** Layout: path building ONLY in `dbFiles.dealFilesDir()`; everything else in `db/dealFiles.js` (it requires
  db/dbFiles.js and only the `SLIDE_SANDBOX_CSP` constant from lib/slideUpload.js — no cycle, slideUpload requires
  dbFiles lazily). The read auditor is a sibling module so the Phase 11 denial auditor and its tests stay untouched.
  Kind table: `communications` (exts html), `media` (png, jpg, jpeg, webp, pdf — the shipped `MEDIA_TYPES` set),
  `slides` (html, htm, pdf, png, jpg, jpeg, webp). No new table, no schema change — committed DBs stay byte-identical
  (D-14-01). The db -> lib require of one constant is accepted as is (checker I-6: no cycle).
- **PD-2** Server-minted names, checked case-SENSITIVELY after Express decoded `:file` (a `%2F` arrives as `/` and
  fails): communications `^comm_[a-z0-9]{1,64}\.html$`, media `^media_[a-z0-9]{1,64}\.(?:png|jpg|jpeg|webp|pdf)$`,
  slides `^slidefile_[a-z0-9]{1,64}\.(?:html|htm|pdf|png|jpg|jpeg|webp)$`. fileId = name minus extension; comm and media
  fileIds ARE the record ids (`newId('comm')`, `newId('media')`), slide fileIds are `newId('slidefile')`. Every
  Windows-only spelling (`.`/space-trailing, `:` streams, `~` short names, `\`) fails the regex by construction.
- **PD-3** Publish: `ensurePrivateDir(kindDir)` (0700 for every dir it creates), `assertTestIsolation(final)` first,
  temp `.<name>.<8 hex>.tmp` opened `wx` mode 0600, write, `fsyncSync`, close, `linkSync(temp, final)` (EEXIST-atomic
  no-overwrite publish), unlink temp; where hard links are unsupported (EPERM/ENOTSUP/ENOSYS) `copyFileSync(temp,
  final, COPYFILE_EXCL)` then unlink temp; any failure removes the temp and rethrows. Temp names start with `.` so the
  route regex never matches them and `kindBytes()` never counts them.
- **PD-4** Three `app.get(...)` registrations sharing one `serveDealFile(kind)` factory (the route inventory only reads
  string paths; Express answers HEAD from GET). Order: (1) regex -> 404; (2) `req.dealContext.kind !== 'deal'` -> 404;
  (3) comm/media record check via `readCollections` (comm: `communications` OR `customCommunications` record with
  `id === fileId` AND `htmlEmailPath === '/api/files/communications/' + name`; media: `media` record with `id === fileId`
  AND `url === '/api/files/media/' + name`; slides: owned by the deal's slides dir, no record) -> 404; (4)
  `openDealFile()` (lstat regular file, open with `O_NOFOLLOW` where defined, fstat regular file) -> 404; (5) audit
  (HEAD audited like GET); (6) explicit headers + `Content-Length` + stream from the fd. Never `res.sendFile` /
  express.static (they add Range, ETag and Last-Modified and resolve paths with the platform path module). Every 404 is
  the fixed `{ error: 'Not found' }`, unaudited. A kind marked `clearanceScoped` in FILE_KINDS must call
  `recordVisibleTo` before serving — none is today (Phase 18 seam, a comment + table flag, no code path).
- **PD-5** Auditor semantics (key = actor|dealId|kind|file): no live entry or an expired one -> if the expired entry
  has `pending > 0` emit the folded row `{ kind, file, count: pending, folded: true, windowStartedAt }` first, then
  emit the immediate row `{ kind, file, count: 1 }` and open a fresh 15-min window; a live entry -> `pending += 1`, no
  row. The opportunistic sweep (throttled, at record()) and the unref'd sweeper flush expired pending counts AND delete
  the entry, so the next read always opens with an immediate row. Map cap (default 10,000): when full after a sweep, a
  new key's read is written immediately with `untracked: true` and never inserted (never dropped, never grows memory).
  NO SWALLOW: a throwing `write` propagates and leaves the state unadvanced. `write` looks up
  `auditHook.recordSecurityEvent` at call time. Clock: `now` = `app.fileReadClock()` when it is a function and NOT real
  mode, else `Date.now()` (the `app.auditClock` precedent). Pending counts are per process and lost on a crash (Phase 20
  adds the SIGTERM flush).
- **PD-6** The three READ rows sit directly after their owner rows. test/deployment-role-matrix.test.js compares
  DEPLOYMENT.md with ROLE_READ_POLICY row for row, so the three DEPLOYMENT.md READ rows MUST land in the same commit as
  the policy rows; this is the ONLY DEPLOYMENT.md hunk outside plan 14-09, which owns all Phase 14 prose and re-checks
  these rows.
- **PD-7** `demoLaneDir(kind)`: communications = `MA_DEMO_SENT_EMAILS_DIR` || `<repo>/public/sent_emails`; media =
  `MA_DEMO_MEDIA_DIR` || `<repo>/public/uploads`; resolved once; throws in real mode (the demo lane never writes files
  there). When an override is set (dev/demo only) a static mount for that dir (`index: false`, `redirect: false`,
  `dotfiles: 'deny'`, fallthrough) is registered at the legacy prefix immediately BEFORE the public express.static, so
  overridden demo-lane files stay reachable at their legacy URLs and the tracked showcase email still falls through to
  public/. Unset -> no mount, byte-for-byte legacy. This plan wires the communications override + mount; 14-03 wires
  media's mount.
- **PD-8** `test/helpers/deal-files-server.js` (the egress-server.js pattern): `startFilesServer({ dir, mode:
  'real'|'dev', env })` boots `require('./server.js')` in a child on loopback with isolated MA_* paths (real: MA_MODE=real
  + MA_DATA_DIR=<dir>; dev: temp copies of the committed DBs + MA_DEALS_DIR), seeds accounts admin / il (hrbp) / il2
  (hrbp) / pmo / emp, deal A (members il, il2, pmo, emp) and deal B (member il2) via the deal-fixture path, and mints
  sessions: il, pmo, emp, adminA bound to A; il2 bound to B; admin unbound. Exposes `base`, `tokens`, `dealIds`,
  `dataDir`, `request(path, { token, method, body, headers })`, `stop()`; plus `publicTreeHash()` (sha256 over each
  sorted relative path + the sha256 of its bytes under public/). The isolation guard stays active (NODE_TEST_CONTEXT
  inherited).
- **PD-9** Deal-lane comm record = today's fields with `htmlEmailPath: '/api/files/communications/<id>.html'`,
  `fileBytes`, `fileSha256` (hex); the demo-lane record shape and URL are unchanged byte-for-byte (D-14-04).
