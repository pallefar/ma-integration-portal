## Planner decisions (this plan)
- **PD-5** The runner never writes a committed file (data/demo.db, data/control.db): at user_version 0 with every
  baseline table present such a file is reported as version 1 `implied: true`; a non-baseline migration pending on a
  committed file marks not-ready ('committed-file-needs-regeneration') — regenerating committed files is a deliberate
  developer commit, never a boot side effect. /healthz reports family, migration id, reason and basename only; a deal
  file is reported as `deal`, never by id (the endpoint is unauthenticated).
- **PD-6** A fresh file (no user tables) is created from its schema and stamped at the family's latest version
  without running migrations; an existing file runs pending migrations BEFORE the idempotent schema exec. Each
  migration and its user_version bump share one BEGIN IMMEDIATE with the version re-read under the lock (two processes
  never run one migration twice). A failed migration or quick_check is sticky per path until restart; an SQLITE_BUSY*
  during migration is the normal retryable 503, never a not-ready failure. Boot keeps listening when a family is not
  ready so /healthz can report it; requests touching that file fail closed (central 503 `retryable: false`, or a route's own generic 500 where it already catches locally — never a 2xx).
  (Revision 1: the earlier "a deal file migrates on the first request bound to it" is replaced by PD-27's boot sweep —
  checker W-5; SC3 / PRD acceptance 3 are met literally, no narrowing.)
- **PD-27** (revision 1, checker B-1 + W-5) Boot opens EVERY file family before listen: after the control-plane open,
  `bootOpen('audit', () => auditHook.getAuditConnection())` (so the audit family's migrations — 12-13's legacy-file
  migration — run at boot, never lazily inside a request or nested inside a deal file's `.immediate` write
  transaction), then `bootOpen('deals', sweep)`: for every deal in `controlStore.listDeals()` whose file
  `dbFiles.dealDbPath(id)` EXISTS — active deals through the resolver's shared cache `getOrOpenConnection(path,
  DEAL_SCHEMA_PATH)` (the first request reuses that connection: no second quick_check), archived deals through
  `dbFiles.openDbFile(path, DEAL_SCHEMA_PATH)` closed immediately (no request can bind an archived deal) — each deal in
  its own try that catches only DbNotReadyError (readiness records family `deal`, file `deal`, never the id) and moves
  on. A registered deal whose file is absent is skipped — boot never creates a deal file. Bounded: one open + one
  quick_check per existing registered deal file, no network; logs `[readiness] deal sweep: <n> opened, <k> not ready,
  <ms> ms` (no ids). A deal file created after boot (deal create) is fresh and stamped at the latest version.
- **PD-28** (revision 1, checker W-2) A `backup: true` migration (12-13's legacy-audit migration on files up to 5 GB)
  first checks `fs.statfsSync(dirname(file))` (bavail × bsize): less than 3 × file size + 64 MB free →
  markNotReady(reason 'insufficient-disk-for-migration') + DbNotReadyError, nothing written (backup + partition copy +
  rebuilt file/WAL ≈ 3× the file at peak). A `VACUUM INTO` that throws removes its partial `.bak`. A `.pre-v<id>.bak`
  left by an interrupted earlier attempt while the file is still below version id is deleted and re-taken (the file
  itself is still the unchanged pre-version state — the failed migration rolled back — so no backup gap of
  consequence). The free-byte reader is injectable (`ctx.freeBytes`, test-only, ignored when MA_MODE=real).
