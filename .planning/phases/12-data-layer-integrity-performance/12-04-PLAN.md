## Planner decisions (this plan)
- **PD-14** One persistent, `unref`'d worker_thread per route (pack, rag-pdf), lazily started, respawned after a crash,
  terminated after 60 s. The main thread keeps `getReportPack()` as the availability gate (portability tests unchanged)
  and all data assembly; workers receive plain data and never open SQLite (Phase 8 D-03). If EITHER worker module
  fails to load or run inside a worker_thread — report-pack (`@napi-rs/canvas`) or rag-pdf (`pdf-parse` / pdfjs-dist,
  which polyfills through `@napi-rs/canvas` and may try to start its own fake worker) — e.g. `Module did not
  self-register`, a not-context-aware native addon, or a pdfjs fake-worker / dynamic-import error, THAT task uses
  `createIsolatedTask({ mode: 'process' })` (`child_process.fork`, identical API) — decided here per task, not
  improvised (checker W-9). The SUMMARY records the shipped mode per task. A second concurrent request is REFUSED with
  429 + `Retry-After: 5` (ROADMAP SC5 "refused or queued" → refused, per D-12-05 "never queued unboundedly").
- **PD-15** The permanent-503 marker is the body field `retryable: false`; the client peeks it only when
  `Response.clone` exists (the existing harness fakes have no clone, so Phase 8 behaviour is byte-for-byte unchanged)
  and then neither retries nor shows the busy toast.
