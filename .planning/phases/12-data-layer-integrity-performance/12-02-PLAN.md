## Planner decisions (this plan)
- **PD-24** An audit delta is pushed only when a statement actually changed a row: every INSERT, a changed UPDATE with
  `changes > 0`, a DELETE with `changes > 0`. A row a concurrent writer already deleted is not "changed by this write"
  and is not audited (today it is). Snapshot refreshes (FA-4 generalised to inserts, changed rows, re-seq'd rows and
  deletes) are applied only after the transaction commits, so a rolled-back write never mutates the caller's baseline
  and a second writeDb() on the same object writes and audits only new changes.
- Seq bookkeeping lives in a separate non-enumerable `__seq` map; `__snapshot` keeps its id → raw shape (no test
  inspects its values, but several reference the property).
