## Planner decisions (this plan)
- **PD-19** Clear-Site-Data is honoured only in secure contexts (https or localhost); a plain-http LAN host ignores it,
  so the client clearing is the cross-context guarantee. `LANGUAGE_KEYS = ['employeeLanguage']` (grep-proven; the
  executor re-greps every `localStorage.(get|set)Item('…lang…')` key and records the final list). Order: snapshot
  language keys → POST /api/auth/logout → `sessionStorage.clear()` → remove every other localStorage key → delete
  every Cache Storage entry → unregister service workers → restore language keys → navigate to /login.html. A failed
  fetch still clears client state and navigates. Applies in both modes (mode-neutral hardening).
- **PD-20** Legacy clean-up: flag `ma.legacyCleanup.v1` in localStorage; unregister registrations whose script URL path
  is `/sw.js`; delete only `LEGACY_CACHE_NAMES`, derived from `git log -p -- public/sw.js public/js/transitions.js` (every
  `caches.open(` name ever used; empty if none — record the search); `MODEL_CACHE_NAMES = ['transformers-cache']` are
  never deleted by it. Logout (PD-19) deliberately clears every cache incl. the model (acceptance 5: `caches.keys()`
  empty after logout).
- **PD-26** The no-store middleware sits before the body parsers so parser errors are covered; it matches the canonical
  `/api` prefix exactly as the existing CR-01 guard does (non-canonical spellings are answered 404 before it).
- **PD-34** transitions.js loads client-storage.js through the existing id-guarded dynamic loader pattern (no edit to the
  18 page HTML files); the logout handler uses `window.MAClientStorage` when present, otherwise still performs the
  server logout and navigation (the server header covers secure contexts) — recorded as the one degraded path.
