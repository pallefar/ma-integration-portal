## Planner decisions (this plan)
- **PD-22** page-layout chrome (region wrapper with `data-cms-layout`, BADGE, hero/cards/cta) is trusted template code
  built with createElement/textContent (CTA hrefs pass the same scheme check MASafeHtml uses); ONLY CMS HTML strings
  (richtext `data.html`, legacy `body`) go through MASafeHtml — the never-allowed list contains `button`, which the
  templates use, so templates must not be routed through the content renderer.
- **PD-28** safe-html.js is loaded by a static parser-blocking script tag on each of the 18 pages (one identical line
  each, inserted immediately before the page's first `<script src="/js/…">` among transitions.js / page-layout.js /
  employee.js / the page's own script), so MASafeHtml is defined before any consumer runs — chosen over a dynamic
  loader because two render paths (i18n-html apply, page-layout fetch callback) can run before a dynamically inserted
  script executes. File-count note for the checker: 22 entries, 18 of which are this one mechanical line, verified by
  one ordering test.
- **PD-36** MASafeHtml semantics mirror the server: DROP_WITH_CONTENT_TAGS removed with content; other non-allowlisted
  elements unwrapped; elements outside the HTML namespace (SVG/MathML) dropped with content; comments dropped; URL
  attributes resolved with `new URL(value, location.origin)` after stripping control characters, protocol must be in the
  allowlist (relative URLs resolve to the page origin → allowed), `data:` only for `img` with an allowlisted image MIME
  and base64; `style` copied property-by-property through a detached element's CSSStyleDeclaration filtered by the
  CSS allowlist; `a` gets `rel="noopener noreferrer"`, `target` only `_blank`. `POLICY` is plain frozen data built at
  load time without touching DOM APIs (so a vm without a DOM can read it).
