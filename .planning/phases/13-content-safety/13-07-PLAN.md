## Planner decisions (this plan)
- **PD-10** Report-only never weakens today: report-only mode = legacy enforcing policy (today's directives with
  `'unsafe-inline' 'unsafe-eval'`, third-party origins from the egress switch, plus `report-uri`) + strict policy as
  Report-Only; enforce = strict only (with `report-uri`). Unknown CSP_MODE fails closed to enforce.
- **PD-11** Only `report-uri` is emitted (no `report-to` / Reporting-Endpoints): Chromium ignores report-uri when report-to
  is present and batches report-to deliveries by up to a minute, which would make walk assertions racy. The endpoint
  still parses `application/reports+json` (array of `{ type: 'csp-violation', body: {…} }`) for other agents.
- **PD-25** Store = per-process memory; key = `${effectiveDirective}|${blockedUri}|${sourceFile}`; strings truncated to
  200 chars; URL-valued fields reduced to origin + path (query and fragment dropped — they can carry MNPI such as deal
  ids or search text); insertion beyond 100 distinct evicts the least recently seen; per-IP token bucket 60/min (req.ip,
  TRUST_PROXY-aware); body limit 4 KB via the route-level parser; response 204 with no body. No admin UI this phase — the
  JSON list is what the walks assert on. A multi-process deployment lists per process (documented by 13-13).
- **PD-37** Slide responses keep only their sandbox CSP: 13-03 already removes the Report-Only header on the slides mount;
  this plan adds a regression subtest so the strict Report-Only policy never reports a slide's own inline scripts.
