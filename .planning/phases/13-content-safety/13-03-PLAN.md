## Planner decisions (this plan)
- **PD-16** HTML is sent as utf8 text (today's client contract); PDF/PNG/JPEG/WebP as base64 with `encoding: 'base64'`
  and the browser's `type`. Extension ↔ MIME table: html/htm ↔ text/html; pdf ↔ application/pdf (`%PDF-`); png ↔
  image/png (`89 50 4E 47 0D 0A 1A 0A`); jpg/jpeg ↔ image/jpeg (`FF D8 FF`); webp ↔ image/webp (`RIFF????WEBP`). An
  HTML upload whose first bytes match a binary signature is refused. Size limit applies to decoded bytes. Quota = sum
  of file sizes in slidesDir() at upload time + this file; a concurrent cross-process overshoot of at most one file is
  accepted (uploads are rare, admin-only).
- **PD-17** PDFs are framed WITHOUT the sandbox attribute and served without the sandbox CSP (Chromium refuses to render
  a PDF in a sandboxed frame/document); they keep nosniff, the app's own CSP and magic-byte verification — a PDF cannot
  run script in the portal origin. HTML and images get the sandbox in both layers.
- **PD-18** Dedicated mount `app.use('/uploads/slides', express.static(slidesDir(), { dotfiles: 'deny', index: false,
  setHeaders }))` placed BEFORE the terminal `.html` middleware (B-1 — a mount after it never sees a default-directory
  `.html` slide, because that middleware answers it via sendHtml with the app CSP) and after the credential-lockdown gate
  and the global security-headers middleware: only allowlisted extensions are served (others 404 via a guard
  middleware on the same path), `Cache-Control: private, no-cache`, sandbox CSP + nosniff for html/images,
  `res.removeHeader('Content-Security-Policy-Report-Only')` for every slide response. The mount is TERMINAL for its
  prefix: a final `app.use('/uploads/slides', …)` handler answers 404 text/plain for anything the static did not serve
  (not `fallthrough: false`, whose 404 would route through the error middleware), so neither sendHtml nor the public
  express.static can serve a slide path — this also stops legacy files left in public/uploads/slides from being served
  unsandboxed when MA_SLIDES_UPLOAD_DIR points elsewhere. Express matches the mount path case-insensitively; the
  pass-through added to the terminal `.html` middleware (`return next()` when `req.path` matches
  `/^\/uploads\/slides\//i`) is defence in depth so `rewriteHtml` never touches slide bytes even if the order regresses.
  Existing uploaded files (all .html) are served sandboxed from the first request after deploy.
- **PD-33** The client sends the fixed refusal `error` text to the admin via textContent; it never echoes the server body
  as HTML.
