<objective>
Turn the dashboard into the deal home when a session is bound to a real deal: what is still outstanding from
setup, how far the readiness assessments have got, where diligence stands per area, and what the person
looking at it personally owes.

Purpose: D-19 closes the loop the wizard opens — a deal created with skipped steps needs somewhere that says
so. 04-RESEARCH.md verified that `public/js/dashboard.js` has zero deal-awareness today, so this is genuinely
new rendering, not a retrofit of the demo panels. D-21's nudges are what stop an assigned DD item from
quietly aging past its due date.

Output: the rollup endpoint, the deal-home panels, the owner nudge, and a human check that the demo showcase
is unharmed.
</objective>

<interface_contract>
`GET /api/dd/summary` response:
`{ areas: [{ area, label, items: { total, open, requested, received, reviewed, closed, blocked, overdue },
   findings: { total, low, medium, high, critical, open } }],
   totals: { items, overdue, findings, criticalFindings },
   mine: { openItems, overdueItems, openFindings } }`

- `areas` contains ONLY the areas the caller is cleared for, in `DD_AREAS` declaration order. An uncleared
  area is absent — never present with zeroes.
- `totals` sums the areas actually returned, so the number a caller sees is the number they are entitled to.
- `mine` counts rows whose `owner` equals the calling username, within the caller's cleared areas.
- `overdue` reuses the same computation the item routes already apply — one implementation, not a second.

Deal-home container: `public/dashboard.html` gains `<div id="deal-home">` immediately after the existing
empty-state block, hidden by default. `public/js/dashboard.js`'s deal-bound branch shows it and hides both the
existing main view and the existing empty state. The demo path is untouched.

Rendering split: ALL new deal-bound rendering lives in a NEW file `public/js/deal-home.js`, an IIFE-wrapped
module exporting `window.renderDealHome(dealId)`. `public/js/dashboard.js` gains only a short branch that
decides which world it is in and delegates. This keeps the new, text-only rendering in a file that can be
grep-asserted as a whole, without auditing 2400 lines of pre-existing demo rendering that legitimately uses
markup assignment for showcase content.
</interface_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> GET /api/dd/summary | An aggregate view of MNPI crosses here; an aggregate leaks differently from a list |
| deal home rendering -> the viewer's eyes | A count, a label or an empty row can disclose the existence of a restricted area |
| owner nudge -> the physical screen | A banner is read by whoever is near the screen, not only the signed-in user |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-45 | Information Disclosure | `GET /api/dd/summary` | critical | mitigate | Areas are filtered before any tally; an uncleared area is omitted entirely rather than returned with zeroes, and `totals` sums only the returned areas so the aggregate itself carries no residue of the hidden ones |
| T-04-46 | Information Disclosure | deal-home panels | high | mitigate | The page renders only what the endpoint returned and holds no client-side list of all eight areas; asserted by the response-shape tests plus the human check that uncleared areas are absent rather than greyed |
| T-04-47 | Information Disclosure | owner nudge banner | medium | mitigate | The banner names counts only — never an area, an item title or another person's name — because it is legible to anyone near the screen |
| T-04-48 | Information Disclosure | an activity feed creeping onto the deal home | medium | mitigate | No feed is built and no audit route is referenced from the dashboard script, asserted by a source check; D-20 keeps an Integration-Lead-scoped audit read deferred |
| T-04-49 | Tampering | archived-deal writes from the deal home | medium | mitigate | The resolver already refuses a write bound to an archived deal; the deal home renders its rollups read-only for a retained member (D-22), so a refused write is never presented as a success |
| T-04-50 | Denial of Service | the demo showcase broken by the deal branch | high | mitigate | The demo path returns before any new code runs and is verified by an explicit human regression check first, not last — the showcase is a maintained deliverable |
| T-04-51 | Information Disclosure | deal content leaving the app | high | mitigate | Nudges are in-app only (D-21); no mail, webhook or third-party call is added anywhere in this phase |
</threat_model>
