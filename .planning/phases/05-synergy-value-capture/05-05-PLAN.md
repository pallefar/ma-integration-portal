<objective>
Deliver SYN-05's data half: an explicit confirmation stamp with deliberate semantics (D-16), a
per-deal staleness threshold and phasing horizon (D-17, D-03), and a server-computed rollup that
splits the headline realized figure into confirmed and unconfirmed portions alongside gross, cost
and net benefit (D-18, D-21), plus the caller-scoped stale count the deal-home nudge reads (D-19).

Purpose: freshness is only as honest as the mechanism that stamps it. A stamp any write can touch
tells you nothing; a stamp only a deliberate act can touch is a claim somebody stands behind.
Output: one new write route, one new read route, two new deal settings, and a new test file.

Planner note (D-19 scope clarification, flagged): `public/js/deal-home.js` renders only for a
deal-bound session, so the stale-initiative nudge is a real-deal surface and does not appear in the
demo showcase. The UI-SPEC's demo requirement is satisfied by the two demo-visible surfaces — the
card badge and the rollup's unconfirmed sentence, both in `public/js/execution.js`. This plan
therefore builds one caller-scoped count on a route both surfaces can read, rather than inventing a
demo-mode deal-home.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `POST /api/synergies/:id/confirm-current` | A write that changes only a freshness claim; its trust value depends entirely on it being unreachable by accident |
| Browser → `POST /api/settings` | An untrusted body that can change the staleness threshold and the phasing horizon for the whole deal |
| Browser → `GET /api/synergies/rollup` | A read whose `mine` figure is scoped by the server-resolved session identity, never by a client-supplied username |
