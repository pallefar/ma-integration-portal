## Deviations from Plan

### Auto-fixed / intent-preserving

**1. [Rule 3 - Blocking] Soak harness fabricated sessions for non-existent accounts**
- **Found during:** Task 2 (`npm run soak`)
- **Issue:** `soak: failed to create the shared conflict-probe RAID entry (status 401)`. `scripts/soak.js` creates `soak-worker-N` sessions directly in runtime.db; Phase 10 (D-10-04, COLLAB-02) re-reads identity from control.db per request, so a session without an account is 401. A direct consequence of this phase, not pre-existing.
- **Fix:** `createWorkerSessions` seeds a credential-less admin account row per worker through `controlStore.createAccount` (no hash, cannot sign in). Product code untouched.
- **Files modified:** scripts/soak.js - **Commit:** `ec75065`. Soak then PASS on the first full run.

**2. [Plan intent] demo-committed lane proves the stronger no-account-surface form**
- **Issue:** the plan asked for an admin sign-in and a disabled header menu in `demo-committed`. Under `DEMO_OPEN=1` the server treats every request as the open demo and ignores a session cookie (`/api/auth/me` -> `authEnabled:false, user:null`), so no account menu or Users tab exists to disable. A signed-in probe confirmed it.
- **Fix:** the scenario branches on `/api/auth/mode.demoOpen`: demo-open asserts no `[data-am]` items on an app page at both widths, the admin console is not reachable cookie-less (stays on `/login.html`) with no Users tab / Add user, the change-password page offers no enabled form, and POST `/api/admin/users` is 401. The signed-in checks (and shots named in the plan) run in `dev-committed`.
- **Files:** scripts/uat/phase10-scenarios/acceptance.js - **Commit:** `471227d`

**3. [Plan intent] Extra evidence shots and removed stale evidence files**
