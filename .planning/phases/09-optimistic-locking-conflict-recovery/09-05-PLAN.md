**server.js — `POST /api/org/positions`.** Inside the `if (b.id)` branch, call `conflictIfStale` after
the existing not-found guard and after the employee-existence check, but BEFORE the shallow-merge
`candidate` evaluation and the `positionGraphFailure` call — and therefore before any field of the
stored row is assigned. The handler's own comment records why: `readDb()` hands back a shared cache, so
any mutation followed by a refusal sticks. Order the two refusals so that a request which is both stale
and structurally invalid gets the conflict, since the conflict is the actionable one for the user.

Pass no clearance filter here. Unlike DD, the whole route is gated on a single `hr` area grant checked
at the top, so a caller reaching the conflict path is already cleared for every record the route can
resolve — a per-record filter would be a second, parallel check of the same fact.

**server.js — `POST /api/org/flight-risk`.** Same placement: after the not-found guard and the
employee-existence check, before the first field assignment.

**server.js — `POST /api/org/decisions`.** Add no precondition. Instead add a short comment at the
route recording the exemption and its reason: the route only ever pushes a new entry, and no route
anywhere in the app exposes an update or delete path for a decision, so there is no mutable write for a
version check to guard. Reference the requirement text explicitly, since CONC-02 names "org decision"
among its examples and a future reader will otherwise read the absence as an oversight. A decision
record therefore never carries a `version` field.

**validators/org.js** — add `version: z.number().int().nonnegative().optional()` to the org position
schema and the flight-risk schema.

**test/optimistic-locking-contract.test.js** — append: a stale-version org-position update returns 409

advances the version by one; the same pair for a flight-risk entry; a case proving that an org-position
update that is both stale AND graph-invalid returns the 409 rather than the 400; and an assertion that
`orgDecisions` is absent from `VERSIONED_COLLECTIONS` with a comment citing the append-only finding, so
a future developer adding it has to confront the reason.
  </action>
