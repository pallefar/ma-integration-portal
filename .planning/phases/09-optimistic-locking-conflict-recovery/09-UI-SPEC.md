# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the shared conflict-compare dialog (409 recovery, D-03/D-04/D-05) and its stale-delete variant (D-08), rendered from `public/js/transitions.js`'s fetch wrapper. No new page, no new nav surface — this is one reusable modal component that every co-edited write surface inherits automatically.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — vanilla JS, no framework, no build step (shadcn gate not applicable: tech stack is not React/Next.js/Vite, per project CLAUDE.md) |
| Preset | not applicable |
| Component library | none — hand-rolled CSS in `public/css/style.css` against an established `:root` token set (TE Connectivity brand) |
| Icon library | none in use for modals/toasts in this codebase — text/symbol glyphs only (e.g. `×` close button, per `.playbook-modal-x`); Phase 9 introduces no icon dependency |
| Font | Inter (`--font-family-sans`, body/UI text) + Outfit (`--font-family-display`, headings) — both already loaded via the existing Google Fonts `@import` in `style.css:1` |

**Existing component to extend, not replace:** `.deal-modal-overlay` / `.deal-modal` (`public/css/style.css:8232-8249`) is the closest structural precedent — fixed-position centered overlay, `rgba(15,30,38,0.72)` scrim, `backdrop-filter: blur(3px)`, white card, `border-radius: 14px`, `box-shadow: 0 24px 70px rgba(0,0,0,0.4)`. The conflict dialog reuses this shell pattern under new class names (`.conflict-modal-overlay` / `.conflict-modal`) rather than inventing a new visual language, sized wider (see Spacing) to fit a field-diff list. The general `.modal-overlay`/`.modal-content` show/hide transition classes (`style.css:3005-3027`) may be reused for the open/close animation if convenient — not required.

**Focal point and visual hierarchy (checker Dimension 2):** the **field-diff list is the focal point** — it is the decision surface comparing the user's value against the server's current value, and the "mine" value-box's orange left accent border is what draws the eye first. Visual hierarchy flows top-to-bottom: header (dialog title + attribution line) → diff-list body (the dominant region by area; scrollable on overflow) → action footer (one orange primary, one neutral secondary). No other element in the dialog may compete with the diff list for visual weight — the header and footer stay chrome-light so the comparison itself reads as the point of the dialog.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a field-diff row's label and its value box |
| sm | 8px | Gap between stacked field-diff rows; gap between action buttons |
| md | 16px | Padding inside a single field-diff value box; gap between dialog sections (header / diff-list / actions) |
| lg | 24px | Dialog outer padding (all four sides) |
| xl | 32px | Not used in this component |
| 2xl | 48px | Not used in this component |
| 3xl | 64px | Not used in this component |

Exceptions: the surrounding legacy modal chrome (`.deal-modal`, `.playbook-modal`) uses non-grid rem fractions (e.g. `0.82rem`, `0.85rem` padding/gaps) rather than a strict 4px scale — an inherited codebase pattern, not something to fix in this phase. All **new** spacing this phase introduces must sit on the 4px scale above; do not copy the legacy fractional values into new rules.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (field values, dialog copy) | 14px | 500 | 1.5 |
| Label (field names, attribution, buttons) | 13px | 700 | 1.4 |
| Heading (dialog title) | 18px | 700 | 1.2 |
| Caption (relative timestamp, helper text) | 12px | 500 | 1.4 |

Exactly 2 weights in use: **500 (regular)** for body/caption text, **700 (semibold)** for labels, the dialog title, and button text. The dialog title uses `--font-family-display` (Outfit) at 700 — Outfit's own letterforms read as sufficiently bold at 700 without needing an 800 weight, so this component does not need a third weight even though adjacent legacy modals (`.deal-modal-title`) use 800.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg-white` (`#FFFFFF`) | Dialog card background |
| Secondary (30%) | `--bg-light` (`#F8FAFC`) + `--border-color` (`#E2E8F0`) | Field-diff row backgrounds ("theirs" column), dialog scrim (`rgba(15,30,38,0.72)`), hairline borders between rows |
| Accent (10%) | `--te-orange` (`#E98300`) | The **"Apply my changes anyway"** primary button only, and the "mine" column's value-box left border/highlight (so the user's own edit visually reads as the "live" one they're being asked to confirm) |
| Destructive | `--status-danger` (`#EF4444`) | The stale-delete variant's **"Delete anyway"** button only |

Accent reserved for: the primary CTA button background (`.conflict-btn-apply` / equivalent to `.btn-primary`) and the "mine" value-box's left accent border in the field-diff list. Never used for the dialog chrome, the "theirs" column, labels, or body text — orange stays scoped to "this is the action that carries your intent forward."

Secondary structural color note: `--te-dark-teal` (`#244C5A`) is available (used for `.btn-secondary`/`.playbook-modal-head`) but is **not** used in this component — "Discard mine, keep theirs" and "Cancel" use the existing plain `.btn-secondary` (transparent, dark-teal border/text) so the dialog has exactly one colored action (orange primary) and one neutral action, keeping the 60/30/10 discipline legible at a glance.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Dialog title (edit conflict) | "Someone else updated this" |
| Dialog title (stale delete, D-08) | "Someone else updated this — still delete it?" |
| Attribution line | "Changed by **{name}**, {relative time}" — e.g. "Changed by karen, 2 min ago" (sourced from the 409 body's actor/time fields; textContent only, never innerHTML) |
| Body intro (edit conflict) | "Your changes are still here. Review what changed below, then decide how to proceed." |
| ~~Field-diff empty fallback~~ | **Superseded by Amendment A3 (2026-10-10).** The sentence "No conflicting fields — the record's version changed without affecting anything you edited. Apply your changes to continue." is retired and is never rendered by any branch; see "Neutral panel" below. |
| Neutral panel (no payload field maps to a record field — A3) | "This record changed since you loaded it." — one sentence, shown in place of the diff rows; "Apply my changes anyway" and "Discard mine, keep theirs" are still offered |
| Dialog title (update landed on a deleted record — A1) | "Someone else deleted this" (`CONFLICT_TITLE_DELETED`) |
| Body intro (deleted variant — A1) | "Someone else deleted this record before your change could be saved. There is nothing left to apply — closing this leaves your form exactly as it was." (`CONFLICT_DELETED_INTRO`); no attribution line is rendered in this variant |
| Single action (deleted and withheld variants — A1, A2) | "Close" (`CONFLICT_CLOSE_LABEL`) — settles with the original 409, sends nothing |
| Withheld-record sentence (409 body `currentRecord` is null — A2) | "This record is no longer within your clearance; your change cannot be applied." (`CONFLICT_WITHHELD_TEXT`) — title "Someone else updated this", attribution as normal, no diff rows, no Apply / Delete anyway, one "Close" |
| Reapply refused (4xx other than a marker 409 — A6) | Banner reason is the server's own `error` text (trimmed, one trailing period removed, at most 200 characters), else "the server refused the change" (`CONFLICT_ERROR_REASON_REFUSED`); a 403/400 is never reported as "a network error occurred" |
| Diff label (A5) | A display label from a fixed table (e.g. "Realized (M)", "Due date", "Reports to", "Stage"); an unknown key is humanised ("someNewField" becomes "Some new field"); per-month phasing cells read "Target (M) · 2026-03". No CSS case transform |
| Primary CTA (edit conflict) | "Apply my changes anyway" |
| Secondary action (edit conflict) | "Discard mine, keep theirs" |
| Primary CTA (stale delete) | "Delete anyway" |
| Secondary action (stale delete) | "Cancel" (keep the record, close dialog, no write is sent) |
| In-flight button label (either primary action, mid re-submit) | "Applying…" / "Deleting…" — button disabled, no spinner icon (matches house convention of no icon dependency) |
| Error state (reapply itself fails again — second conflict, network error, or server error) | Inline banner inside the dialog, above the actions: "That didn't go through — {reason}. Your edits are still here; review the fresh values below and try again." On a genuine second 409 the dialog re-renders in place with the newly fresh "theirs" values (never stacks a second dialog, never discards the "mine" column) |
| Attribution fallback (409 body lacks actor and/or time fields) | "This record changed since you loaded it." — rendered in place of the attribution line; never render "Changed by undefined" or a blank line (defensive rule for D-09 lazy-stamped records or script-mutated data) |
| Destructive confirmation | **Amended by A8 (2026-10-10).** No browser-native `confirm()` precedes or follows a covered delete. The page's question opens the in-app confirm — the same `.conflict-modal` shell — with "Cancel" + "Delete"; when the DELETE meets a conflict that SAME dialog becomes the stale-delete variant ("Someone else updated this — still delete it?", "Cancel" + "Delete anyway"). One surface, two states; "Delete" / "Delete anyway" are the only destructive clicks, consistent with D-08 folding delete-confirmation into the conflict surface rather than stacking two prompts |
| Primary action (in-app delete confirm — A8) | "Delete" (`CONFIRM_DELETE_LABEL`, red/danger — never orange) · secondary "Cancel" (keeps the record, sends nothing) · in-flight "Deleting…" (button disabled) · title is the page's own question via `textContent`; no attribution, no intro |

**i18n decision (prescriptive, not deferred):** this dialog's copy ships as **hardcoded English literals via `textContent`, not wired through `data-i18n` / `applyPortalI18n()`**. Rationale: (1) it is dynamically constructed by JS from a fetch-wrapper interception point, exactly like Phase 8's `showBusyGiveUpToast()` (`transitions.js:57-99`, hardcoded `BUSY_GIVE_UP_MESSAGE`) — the direct precedent for this class of runtime-generated error/recovery text; (2) the attribution line interpolates dynamic data (name, relative time) into copy, which the existing static-key `t(key, lang)` resolver isn't built for; (3) Phase 7's own documented gap (`scripts/seed-reports-i18n.js` header) already treats JS string-literal error/status text as out of the app-wide i18n system's scope. Do not add new `strings.en.*` i18n keys for this component — this is a deliberate, consistent extension of existing house convention, not an oversight to fix later.

## UI Considerations

Probe run 2026-08-11 (ui-consideration-probe, 4 elements: E1 conflict-field-diff-list = list-collection, E2 conflict-action-buttons = interactive-control, E3 stale-delete-confirm-dialog = interactive-control, E4 conflict-dialog-header = static-content; kinds user-confirmed). Applicable: 25 — **resolved 14 (all explicit), dismissed 11 with reason, 0 backstop, 0 unresolved.**

**Resolved (verification: explicit):**

| Category | Element | Resolution |
|----------|---------|------------|
| empty | E1 field-diff-list | Zero rows (no payload field maps to a record field, e.g. confirm-current, convert, re-baseline, cost-entry add) renders the neutral panel "This record changed since you loaded it." (Amendment A3 — the old "No conflicting fields…" sentence is retired) instead of an empty box, and still offers "Apply my changes anyway" |
| populated | E1 field-diff-list | Typical case: 1–4 changed fields, each a stacked two-column row ("mine" left, orange accent border; "theirs" right, neutral background) with the field's display label above |
| partial | E1 field-diff-list | A changed field whose value (mine or theirs) is empty/null renders an explicit italic "(empty)" placeholder in that value box — never blank whitespace, which would read as a rendering bug |
| overflow | E1 field-diff-list | Many changed fields (8+ full-form edit) scrolls the diff-list body internally within a `max-height`; dialog header and action footer stay pinned, non-scrolling — dialog never grows past the viewport |
| zero-one-many | E1 field-diff-list | A single-field change (kanban status flip, D-02) renders as one compact row with no excess whitespace; many fields scroll per the overflow rule — both read cleanly at the same dialog width |
| long-text | E1 field-diff-list values | Long values (RAID description, DD-finding narrative) show the **full** value, wrapped, in a per-field scrollable `max-height` box — never ellipsis-truncated, because the user must see the complete competing value to decide "apply mine" vs "keep theirs" |
| loading | E2 action-buttons | On click, the clicked button enters a disabled "Applying…" label state for the duration of the re-submit fetch. **Amended A9:** the other action (Discard) is disabled with it, and Escape / overlay click are ignored, until the request answers — the reapply is irrevocable once sent, so the page must learn its outcome |
| error | E2 action-buttons | Second conflict / network failure / 5xx on reapply renders the inline error banner (Copywriting Contract) and refreshes the "theirs" column from a second 409's fresh data; the "mine" column is never cleared or reset |
| loading | E3 stale-delete dialog | "Delete anyway" enters a disabled "Deleting…" label state during the resubmit. **Amended A9:** "Cancel" is disabled (and Escape / overlay click ignored) until the resubmit answers |
| error | E3 stale-delete dialog | "Delete anyway" resubmitting into a second conflict (record changed again, or already deleted) re-renders the same dialog shell with refreshed attribution/values — never silently succeeds or silently fails |
| partial | E3 stale-delete dialog | Attribution with missing actor/time follows the E4 fallback rule below |
| empty | E4 header/attribution | 409 body lacking actor **and** time renders the attribution-fallback copy "This record changed since you loaded it." — never a blank line. Amendments A1/A7: the deleted variant renders no attribution line at all, and when the neutral panel already shows that sentence the attribution element is omitted so it never appears twice in one dialog |
| partial | E4 header/attribution | 409 body lacking actor **or** time (D-09 lazy-stamped v0 records, script-mutated data) renders the same fallback copy — never "Changed by undefined" |
| long-text | E4 header/attribution | Long display names wrap onto a second line via `textContent`; the name is never truncated — the user must be able to identify the other editor |

**Dismissed (reason recorded — no silent drops):**

| Category | Element | Reason |
|----------|---------|--------|
| loading | E1 field-diff-list | The diff list renders synchronously from the in-hand 409 response body — no async fetch occurs, a loading state cannot exist |
| error | E1 field-diff-list | The list itself cannot fail to load (data already in hand); the only failure surface is the reapply action, covered at E2-error |
| empty | E2 action-buttons | The action pair is static chrome, not data-driven — always exactly two buttons |
| partial | E2 action-buttons | No data-dependent content in the buttons |
| long-text | E2 action-buttons | Button labels are fixed hardcoded English literals (Copywriting Contract) — no dynamic text |
| empty | E3 stale-delete dialog | No collection inside this variant — content is title + attribution + actions, all static or covered by E4 rules |
| overflow | E3 stale-delete dialog | Fixed content; if field values are ever shown they follow E1's overflow rule |
| long-text | E3 stale-delete dialog | Same — defers to E1 long-text rule for any value display |
| loading | E4 header/attribution | Rendered synchronously from the 409 body — nothing to load |
| error | E4 header/attribution | No failure mode of its own; a malformed timestamp falls back per the E4-partial rule |
| overflow | E4 header/attribution | The wrap rule (E4 long-text) handles width pressure; header height may grow by one line, no clipping |

## Amendments (2026-10-10 — Phase 9 gap closure, plans 09-13/09-14)

Source: `.planning/reviews/v3.0/R7-phase9-uat.md` (F-3, F-4, F-5, F-6, F-7) and gap decisions GD-6..GD-10 in `09-08-PLAN.md`. R7's verdict (item 6) was that these are tweaks to a signed contract, not a new design, so no re-approval cycle is run; they are recorded here, dated, so the contract is explicit rather than silently drifted. All new literals stay **hardcoded English via `textContent`** (the i18n decision above is unchanged; Phase 19 owns localisation of runtime copy). Plan 09-14 adds A8 (the in-app delete confirm). The Round-2 code review (09-REVIEW.md WR-03/IN-04/IN-05) adds A9–A11.

| # | Amendment | Source |
|---|-----------|--------|
| A1 | **Deleted variant.** An update that lands on a record someone else already deleted is titled "Someone else deleted this" (was "This record was deleted"), keeps the intro "Someone else deleted this record before your change could be saved. There is nothing left to apply — closing this leaves your form exactly as it was." and the single "Close" action, and renders **no attribution line**: a deleted row carries no actor or time, so D-04's attribution has nothing true to say. This also resolves FA-2 — the three literals (`CONFLICT_TITLE_DELETED` / `CONFLICT_DELETED_INTRO` / `CONFLICT_CLOSE_LABEL`) are now in the Copywriting Contract. | R7 F-7, GD-10 |
| A2 | **Withheld-record variant.** A version-conflict body whose `currentRecord` is `null` (the record is outside the caller's clearance) renders: the edit title "Someone else updated this", the attribution as normal, the sentence "This record is no longer within your clearance; your change cannot be applied.", **no diff rows, no "Apply my changes anyway", no "Delete anyway"**, and one "Close" action that settles with the original 409. Attribution (who/when) stays visible — the disclosure was accepted as T-09-17 / 09-REVIEW IN-01 — but never a field value. | R7 F-4, GD-7 |
| A3 | **Neutral panel replaces the empty-diff fallback.** When no payload key maps to a record field (`{}` confirm-current, `{toTask,toRaid}` convert, `{reason}` re-baseline, a cost-entry add) the diff area shows "This record changed since you loaded it." and still offers both actions. The sentence "No conflicting fields — the record's version changed without affecting anything you edited…" is **retired** and is never rendered by any branch — the client cannot know the change was irrelevant to the user's edit. | R7 F-3, GD-6 |
| A4 | **Per-route field mapping.** The diff compares what the user edited with what the server holds through a declarative per-route table: a payload key may be an alias for a record field (`targetStage` is `stage`), a cell of an array (a per-month phasing edit compares the same month's `targetM`/`realizedM`, never the initiative total, and is labelled "Label · YYYY-MM"; a month missing on the server shows "(empty)"), or an ignored action parameter. A mapped field whose mine and theirs values are equal is still rendered with both values. | R7 F-3, GD-6 |
| A5 | **Display labels.** Diff row labels come from a fixed display-label table ("Realized (M)", "Due date", "Reports to", "Stage", …) with a deterministic humanised fallback for an unknown key ("someNewField" becomes "Some new field"; a trailing "Id" after a lowercase letter is dropped; a final standalone "M" renders "(M)"). Labels are rendered via `textContent` with **no CSS case transform**. | R7 F-5, GD-8 |
| A6 | **Reapply-failure reason for a 4xx.** A reapply refused with a 4xx other than a marker 409 (a 403 for a clearance change, a 400 refusal, a marker-less 409) shows the server's own `error` text in the banner — trimmed, one trailing period removed, at most 200 characters — or "the server refused the change" when there is none. A 4xx is never reported as "a network error occurred". 5xx and genuine network failures keep their existing reasons. | R7 F-4, GD-7 |
| A7 | **One sentence, once.** The same sentence is never rendered twice in one dialog: when the neutral panel already shows "This record changed since you loaded it." the attribution element is omitted rather than repeating it as its fallback. | R7 F-7, GD-6 |
| A8 | **In-app delete confirm — one surface for a delete.** Every covered delete path opens the in-app confirm in the `.conflict-modal` shell (`window.maConfirmDelete(question, url)`), never the browser-native `confirm()`. The title is the page's existing question, verbatim: **task** "Delete this task?", **RAID entry** "Delete this entry?", **synergy initiative** "Delete this initiative?", **synergy cost entry** "Delete this cost entry?", **org position** "Delete position? This cannot be undone." Actions: "Cancel" (secondary) + red "Delete" (`conflict-btn-delete`, danger style, never orange); in-flight label "Deleting…" with the button disabled. No intro, no attribution (nothing to attribute yet). On a conflict (marker 409) the SAME overlay re-renders in place as the stale-delete variant — title "Someone else updated this — still delete it?", the attribution line, "Cancel" + "Delete anyway" — with **no** "changed again" banner (it is the first conflict). Cancel / Escape / overlay click in the confirm state send nothing and leave the record in place; in the stale state they resolve with the original 409 and the page re-reads (GD-5). While the first DELETE is on the wire the dialog cannot be dismissed. A second click on "Delete" or "Delete anyway" sends nothing; the confirm refuses to open while another conflict dialog is open. A non-conflict refusal (e.g. the org position "direct reports" 400) closes the dialog and the page shows its own error as before. The two native confirms that are **not** delete paths — execution.js generate-phasing ("This replaces the existing phasing rows. Continue?") and the org.js decision-record confirm — are unchanged. Literals remain hardcoded English via `textContent`. Resolves R7 F-6, which found the browser confirm stacked in front of the signed one-surface promise. | R7 F-6, GD-9, SC7 |
| A9 | **Every exit is locked while a reapply is on the wire.** Supersedes the E2-loading "the other action stays enabled" and E3-loading "Cancel stays enabled" rows (both pre-date the held-promise design of 09-11). From the click on "Apply my changes anyway" or "Delete anyway" until that request answers, "Discard mine, keep theirs" / "Cancel" is disabled and Escape / overlay click are ignored — the same rule A8 already set for the confirm state. A 2xx closes the dialog and hands the page that response; any failure re-renders the dialog (banner per E2-error / A6) with every control enabled again. Reason: an exit mid-flight handed the page the stale 409 and triggered a re-read that could land before the irrevocable reapply committed — the page showed "theirs" while the server held "mine". No literal changes. | 09-REVIEW R2 WR-03 |
| A10 | **Keyboard focus is trapped in the dialog.** On open, focus moves to the first enabled action — always the safe one ("Discard mine, keep theirs" / "Cancel" / "Close"), never "Apply my changes anyway", "Delete anyway" or "Delete". Tab / Shift+Tab cycle through the dialog's enabled actions only; focus found anywhere else is pulled back in; while every action is disabled mid-flight (A9) focus rests on the modal itself. On close, focus returns to the element that had it before the dialog opened. Reason: `aria-modal` alone does not trap focus, so Tab + Enter could reach a page delete button behind the overlay, whose in-app confirm then refused silently (A8: "the confirm refuses to open while another conflict dialog is open"). No literal changes. | 09-REVIEW R2 IN-04 |
