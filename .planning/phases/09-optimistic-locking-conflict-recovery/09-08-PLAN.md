<gap_decisions>
Decisions for the whole gap closure (09-08 … 09-16). Taken by the orchestrator (numbers 1–11 in the
planning brief) or by this planner (marked PLANNER). Later plans cite them as GD-n.

- **GD-1 (orch. 1) — F-1 is fixed on both layers.** Client: every call site that edits or deletes an
  existing record sends `window.maVersionOf(rec)` — the record's `version` when it is a non-negative
  integer, else 0. Server: an update OR delete of an existing record that reaches `conflictIfStale()`
  with no precondition is refused with 400 `{ error, versionRequired: true }` unless the request is a
  demo-store request. Demo stays lenient (D-09). A missing stored version is still treated as 0
  (`conflictIfStale`'s `currentVersion` rule), so `version: 0` on a never-edited record passes and is
  rejected with 409 once another writer has stamped it. No INSERT-time stamping, no migration, no
  boot backfill — D-09's "committed demo.db stays byte-identical until genuinely written" holds.
- **GD-1a (PLANNER) — interpretation.** "Update to an existing versioned record" (REQUIREMENTS CONC-02)
  is read as "a write to an existing record of a `VERSIONED_COLLECTIONS` collection", NOT "a record
  that already carries a version field" — the narrower reading would keep never-edited records exempt
  server-side, which is exactly F-1. DELETE is included (D-02 "no exemptions" + D-08 "409 on stale
  delete": a delete with no precondition cannot be judged stale).
- **GD-1b (PLANNER) — fail-closed predicate.** "Demo-store request" is `req.isDemo === true` (set by
  db/resolver.js for `kind === 'demo'`). Every other request — a deal-bound one, or one with no resolver
  context at all — is strict. Orchestrator decision 1 says "deal-bound"; for every request that reaches a
  `conflictIfStale()` route through the resolver the two predicates are identical (control-plane paths
  never reach these routes); the fail-closed form additionally refuses a request whose context is
  missing.
- **GD-2 (PLANNER, measured) — rollout order.** Planner experiment 2026-10-10 on a scratch copy: making
  the rule universal immediately fails 118 existing tests across 25 files; RAID-only fails 6. So this
  tracer wires the rule as an opt-in on the two RAID routes; plan 09-09 extends the opt-in family by
  family together with the suites each family breaks; plan 09-10 folds the rule into
  `conflictIfStale()` unconditionally and deletes the opt-in. The opt-in does not survive the phase.
- **GD-3 (PLANNER) — test helper.** Suites whose subject is NOT the version contract install
  `test/helpers/held-version.js`'s `installHeldVersionFetch()`, which supplies the precondition a real
  client would send (the stored version, or 0) on a versioned-route write that omits one. Explicit-
  contract suites (optimistic-locking-contract, optimistic-locking-precondition,
  optimistic-locking-cross-process, client-*) never install it. Its route table is cross-checked
  against server.js by a structural test so it cannot drift.
- **GD-4 (orch. 2) — F-2:** the fetch wrapper holds the original promise while the dialog is open
  (plan 09-11). **GD-5 (PLANNER):** after Discard/Escape/overlay/Close/Cancel the page re-reads server
  state ("keep theirs" is shown, not just promised) (09-12, together with the client sweep of every
  remaining call site).
- **GD-6..GD-10 (orch. 3–7):** alias map + neutral panel (F-3), withheld-record copy + real 4xx reason
  (F-4), display labels (F-5), in-app confirm that becomes the stale-delete variant (F-6), deleted
  variant without attribution + title "Someone else deleted this" (F-7) — plans 09-13 (F-3/4/5/7) and
  09-14 (F-6).
- **GD-11 (orch. 8):** `?v=` stamp bump + regression test (09-15). **GD-12 (orch. 9):** docs (09-15).
  **GD-13 (orch. 10):** Playwright two-context evidence replaces the human walks (harness here,
  full run in 09-16). **GD-14 (orch. 11):** out of scope — task/RAID write-path clearance (Phase 11
