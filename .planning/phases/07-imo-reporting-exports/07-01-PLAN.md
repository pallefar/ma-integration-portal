<objective>
Prove the whole export architecture end to end on one dataset — RAID as CSV — before expanding to
anything else. This is the phase tracer: one entry point (an anchor in a new Reports & Exports tab)
wired through the Express /api gate, a zod-validated query whitelist, the existing RAID clearance
filter, the CSV writer, a safe Content-Disposition header and the audit hook, to a file on disk.

It carries the phase's four hardest non-negotiables on its single path, so a mistake in any of them
surfaces after one commit instead of after seven: D-08 (the export payload is exactly what the app
would show that caller), D-09 (org and talent data have no export surface at all), D-07 (codename in
the filename, never the legal target name) and D-10/D-11 (every real-deal export is audited, demo is
not).

Purpose: the architecture every remaining export and the PDF pack inherit is decided here.
Output: lib/reportCsv.js, lib/reportFilename.js, GET /api/reports/export, the Reports & Exports tab,
and three test files.
</objective>

    decision checkpoint — but both are expensive to walk back: weakening D-08 later means re-auditing

  </reversibility>
  <action>
    Wire ONE path — RAID as CSV — through every server layer, with real error handling on that path
    and no other call sites.

    Create lib/reportCsv.js exporting csvField(value) and toCsv(rows, columns) as CommonJS. columns is
    an array of key/header objects. Quoting follows RFC 4180: a field containing a comma, a double
    quote, a carriage return or a line feed is wrapped in double quotes with internal double quotes
    doubled. Rows join with CRLF; the output is prefixed with a UTF-8 byte-order mark so a spreadsheet
    opens accented and CJK content as UTF-8 instead of guessing a system codepage. An empty rows array
    must naturally yield mark plus header line plus trailing CRLF with no special-case branch.

    Add spreadsheet formula neutralisation to csvField: a value whose first character is one of the
    four formula-trigger characters is prefixed with a single apostrophe before quoting. This is a
    planner-added hardening, not a locked decision — 07-RESEARCH.md's Security Domain table flagged it
    as a real risk this codebase never had to consider because no export existed before, and asked for
    an explicit in-or-out call rather than a silent one. It is IN. State the rationale in the module
    header: a RAID entry title is free text, one beginning with an equals sign is a plausible
    accident, and the recipient's spreadsheet evaluating it is a tampering vector at the far end of an
    MNPI egress path.

    Create lib/reportFilename.js exporting sanitizeForFilename(raw), buildReportFilename(codename,
    dataset, ext) and setContentDisposition(res, filename). sanitizeForFilename strips C0 control
    characters, the delete character and the Unicode bidirectional-override ranges, trims, and falls
    back to a generic literal when the result is empty. buildReportFilename additionally replaces
    filesystem-reserved characters with hyphens and composes codename, dataset and the ISO date,
    matching 07-UI-SPEC.md §2's locked filename shape. setContentDisposition emits both the ASCII
    quoted-string fallback (non-ASCII bytes, quotes and backslashes replaced) and the RFC 5987
    percent-encoded extended parameter, wrapped in a try/catch that logs via console.error with the
    security prefix convention and falls back to a generic attachment name — a header-encoding error
    must never reach the response.

    In server.js add GET /api/reports/export next to the other read routes. Validate the dataset and
    format query parameters with zod enums: dataset is exactly workstreams, tasks, raid or synergies;
    format is exactly csv or json. A value outside either enum returns 400 with a JSON error and reads
    nothing. This whitelist IS the D-09 control — org and talent datasets are absent by construction,
    so a crafted request naming positions, org decisions or flight risk is refused before any lane
    opens, with no denylist branch to forget to update.

    Implement ONLY the raid-plus-csv combination in this task; every other accepted combination
    returns 501 with a JSON error naming it as not yet implemented (Plan 07-02 replaces those
    branches). The RAID branch calls readDb(), resolves the deal through controlStore.getDeal(), warms
    ddFindingsLane(db), then filters raidLane(db) through the EXISTING resolveRaidEntryClearanceArea
    and accessPolicy.hasAreaGrant — the same two calls GET /api/raid makes, in the same order (D-08).

    RAID CSV columns in this order: id, type, severity, probability, title, owner, workstreamId,
    status. These mirror the fields the RAID tab already shows that caller, per D-08's parity rule.

    Build the filename from the deal's codename field — the same field the header deal-switcher pill
    renders — never the deal's real legal-target field, which exists separately precisely so it can be
    withheld (D-07/D-09). Set Content-Type to text/csv with a utf-8 charset, call setContentDisposition,
    and send the string. Wrap the handler in try/catch that logs via console.error and returns 500 with
    a JSON error, matching the download-zip route's shape.

    After a successful response record exactly one audit event, gated on the request not being a demo
    request (D-10 real deals only; D-11 demo keeps full parity minus audit rows): action report-export,
    actor from the resolved portal user, the bound deal id, subject the dataset string, after an object
    carrying format and row count, request from requestMeta(req). Comment that the audit row's
    database-kind column is written as the control literal by recordSecurityEvent for every caller — an
    accepted, already-documented Phase-6 residual this route deliberately does not work around, because
    writing to the audit connection directly would break the audit isolation guarantee.

    Create test/reports-export.test.js on the raid-access-filter harness. Seed one deal whose codename
    is an ordinary string and whose legal-target field holds a distinctive sentinel appearing nowhere
    else in the fixture. Seed RAID entries spanning: no clearance provenance, stamped to one
    due-diligence area, stamped to a second area. Assert as SORTED ARRAYS OF IDS parsed back out of the
    CSV body, never as lengths, that an admin, an integration lead, a member granted one area and a
    member granted no area each receive from the export exactly the id set GET /api/raid returns for
    that same identity in the same run. Assert the Content-Disposition header and the CSV body each
    contain zero occurrences of the sentinel legal-target string. Assert a deal with no RAID entries
    yields byte-order mark plus header line only. Assert three org and talent dataset spellings each
    return 400. Assert a title beginning with an equals sign returns apostrophe-prefixed, and a title
    containing a comma and a double quote round-trips through RFC 4180 quoting.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/reports/export | Authenticated deal member supplies dataset and format query parameters; response is an MNPI-bearing file that leaves the application |
| deal record → HTTP header | The deal codename, free MNPI text validated only for length, is placed into a Content-Disposition header value for the first time in this codebase |
| exported file → recipient's spreadsheet | Free-text titles authored inside the app are interpreted by a program outside the trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Information Disclosure | GET /api/reports/export raid branch | critical | mitigate | Reuse `resolveRaidEntryClearanceArea()` + `accessPolicy.hasAreaGrant()` verbatim, in the same order as GET /api/raid; four-identity sorted-id parity test against that route in the same run (D-08) |
| T-07-02 | Information Disclosure | filename + Content-Disposition | high | mitigate | Filename built from the deal codename field only; a fixture whose legal-target field holds a sentinel proves zero occurrences in header and body (D-07/D-09) |
| T-07-03 | Tampering | `setContentDisposition()` | medium | mitigate | Strip C0 controls, delete char and bidi overrides; emit RFC 6266 quoted-string plus RFC 5987 `filename*`; wrap setHeader in try/catch with a generic fallback so no encoding error becomes a 500 |
| T-07-04 | Repudiation | export route audit call | high | mitigate | Exactly one `recordSecurityEvent({action:'report-export'})` per successful real-deal export; proven as a before/after row-count delta, zero rows in demo (D-10/D-11) |
| T-07-05 | Tampering | CSV field values at the recipient | medium | mitigate | Prefix any field whose first character is a spreadsheet formula trigger with an apostrophe before RFC 4180 quoting (planner-added, research-flagged) |
| T-07-06 | Elevation of Privilege | dataset query parameter | high | mitigate | zod enum whitelist of four datasets; org and talent variants are structurally absent and refused with 400 before any lane read (D-09) |
| T-07-07 | Denial of Service | export route | low | accept | CSV is a synchronous string join over an already-loaded lane; deal-scale row counts are bounded by the same lanes the live GET routes already serve unbounded |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds ZERO new npm packages and runs no installer. `lib/reportCsv.js` and `lib/reportFilename.js` are in-repo modules; no `[ASSUMED]`/`[SUS]` package exists to gate (07-RESEARCH.md Package Legitimacy Audit: zero new dependencies) |
