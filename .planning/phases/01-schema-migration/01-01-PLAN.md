|----------|-------------|
| npm registry → committed node_modules | Third-party native-binary package enters the committed, shipped codebase |
| repo/release artifact → git history + admin download-zip | Data-at-rest artifacts can leak out of the app into shared channels |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | `npm install better-sqlite3` (supply chain) | high | mitigate | Blocking, non-auto-approvable `checkpoint:human-verify` (Task 1) confirms package legitimacy against npmjs.com before install; pin exactly 13.0.1; confirm no postinstall script ran (Task 2). |
| T-01-02 | Information Disclosure | new `.db`/`.db-wal`/`.db-shm` at-rest artifacts leaking via git or download-zip | high | mitigate | Extend `.gitignore` (sidecars) AND the download-zip `-x` exclusion list (server.js:411) in THIS wave, before the wave-2 migration creates the first `.db` (Task 3). Only the demo `data/ma-portal.db` is ever committed — same precedent as the committed `db.json`. |
| T-01-V8 | Information Disclosure | SQLite file at rest | medium | accept | Rely on OS full-disk encryption as the documented baseline; SQLCipher app-level encryption is explicitly deferred (v2 HARD-01). No app-level crypto added this phase. |
