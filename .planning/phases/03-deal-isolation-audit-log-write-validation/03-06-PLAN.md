<objective>
Close the two validation requirements across the whole write surface: one zod-based pipeline that validates every registered write route (strip unknown keys, reject wrong types, missing fields and over-length values with a clear 400), and write-time HTML sanitization for the fields a schema tags as HTML-bearing — with a coverage test that makes an unvalidated write route a failing test rather than a silent gap.

Purpose: `server.js` currently has zero server-side schema validation and its only sanitizer is a client-side, render-time regex. VAL-01 and VAL-02 close a documented Critical gap, and the schemas are a reusable asset for the write models Phases 4-7 add.
Output: the validator registry and its resource modules, `lib/sanitizeHtml.js`, the gate wiring, and three node:test proofs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser request body → route handler | Untrusted, arbitrarily-shaped JSON crossing into code that writes it straight into a stored blob |
| stored blob → rendered DOM | A value written today is rendered on some page later, possibly by a different code path than the one that wrote it |
| validation error → client, logs, screenshots | An error string travels further than the request that caused it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-31 | Tampering (unvetted keys reaching a stored blob) | validationMiddleware | high | mitigate | Every write route resolves to a zod object schema that strips unknown keys by default (D-13); a route with no schema fails closed rather than passing through; asserted exhaustively by test/write-validation-coverage.test.js against the live route inventory |
| T-03-32 | Tampering (stored XSS) | HTML-bearing fields | high | mitigate | Write-time sanitization of schema-tagged fields via lib/sanitizeHtml.js plus the unchanged render-time textContent discipline and CSP (D-15, two gates not one); round-trip asserted by test/xss-sanitization.test.js |
| T-03-33 | Denial of Service (unbounded stored blob) | free-text fields | medium | mitigate | Every string field carries an explicit maximum length derived from what the UI actually sends; asserted by a source check that no schema declares an unbounded string |
| T-03-34 | Information Disclosure (MNPI reflected in an error) | formatIssues | medium | mitigate | Error strings name field paths and broken rules only and never include the submitted value; asserted by case (a) of test/write-validation.test.js |
| T-03-35 | Information Disclosure (internal schema or stack detail leaked in a 400) | validationMiddleware | low | mitigate | The 400 body is the app's existing single-string shape built from issue paths and messages; zod's native issue object and any stack are never serialized to the client |

| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new package; zod was gated and installed in Plan 03-01 and no sanitization dependency is introduced |
