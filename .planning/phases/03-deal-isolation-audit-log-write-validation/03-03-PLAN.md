<objective>
Replace the flag-and-shadow-array switch with a session-bound resolver: every `/api` request is bound to exactly one SQLite file — `demo.db` or a specific `deals/<id>.db` — before any handler runs, with membership refused at bind time, with the account store and deal registry moved behind a dedicated control accessor, and with the demo-only mechanics hard-gated so they can never touch a deal database. Then cut the app over from `data/ma-portal.db` to the split stores and archive the source.

Purpose: this is ROADMAP success criteria 1 and 2 for Phase 3, and the structural change every later plan depends on — the audit hook needs to know which database a write landed in, and the validation pipeline needs one pipeline for both modes. It is also the phase's highest-risk change: it touches the single consolidated gate that every request already passes through.
Output: `db/resolver.js`, `db/controlStore.js`, an AsyncLocalStorage-bound `db/store.js`, the gate wiring, the cutover, and three node:test proofs.
</objective>

<assumption_delta_decision>
The phase introduces a second (and Nth) database where there was exactly one, and turns a required global (`activeProjectId` / the demo-versus-custom flag) into a per-session choice. Both the pluralization and the required-to-optional cues fire.

- **Primary noun (generalized identity):** the **resolved database context** — `{ kind: 'demo' | 'deal', dealId | null, dbPath }` — carried per request. It, not a global active-project id, is now what scopes every read and write.
- **Decision: promote.** The resolved database context becomes the primary scoping identity for all request-time data access; the demo's own active-project id is demoted to an ordinary demo.db-internal detail of the `demo` variant, meaningful only when `kind === 'demo'`. It is deliberately not kept alongside as a second, still-required global — a global "active project" that outlives the request is exactly the multi-user safety regression D-01 rejects.
- **Invariant test encoding the promoted intent:** `test/deal-resolver.test.js` asserts that for every resolved kind (demo and deal), a read issued inside the request context returns rows from that kind's own file and from no other — so a future phase that reintroduces a process-global "current database" makes the test go red immediately.
</assumption_delta_decision>
