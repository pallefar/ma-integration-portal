<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo working tree → git remote | Anything not gitignored is pushed; a real-deal database or a live session store crossing this boundary is an irreversible MNPI/credential leak |
| app → admin download-zip → recipient's machine | The export is handed to arbitrary recipients; every file not in the `-x` list crosses out of the trust boundary |
| npm registry → committed node_modules | A new dependency is executed with full process privilege and is committed into the repo, so a malicious package persists in every release bundle |
| filesystem → audit.db | An in-process code path could rewrite or delete compliance history if the storage layer permits it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | .gitignore / download-zip exclusion lists | critical | mitigate | Add `data/runtime.db*`, `data/audit.db*`, `data/deals/` to BOTH lists in this plan, before Plan 02 creates the first such file; asserted by test/db-artifact-exclusion.test.js (Pitfall 4: the flat `data/*.db` glob does not recurse into `data/deals/`) |
| T-03-02 | Repudiation | audit_log rows | high | mitigate | `audit_log_no_update` / `audit_log_no_delete` BEFORE triggers RAISE(ABORT) inside audit.db, making append-only structural; asserted in test/db-file-layout.test.js. Filesystem-level tampering stays out of scope per D-09/Deferred (hash chaining deferred to v2) |
| T-03-03 | Tampering (path traversal into the deals directory) | dealDbPath(dealId) | high | mitigate | `dealDbPath()` rejects any identifier not matching the `deal_` id format by throwing, so a caller-supplied id can never escape DEALS_DIR; asserted in test/db-file-layout.test.js |
