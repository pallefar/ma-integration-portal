<objective>
Deliver D-19, D-20, D-21 and D-22: the deal home gains a two-tier organisation panel and a flight-risk
owner nudge, both fed by one new server-computed, clearance-scoped rollup.

Purpose: Phase 4 and Phase 5 each added a deal-home surface; skipping it would make organisation the
only capability in this milestone with no presence on the page an Integration Lead opens first. The
current-to-target headcount delta is the number a steering committee actually asks for, and it is the
one number that cannot be computed anywhere but the server without leaking the target design.

Output: one rollup route whose restricted half is structurally absent for an uncleared caller, a panel
whose two tiers are distinguishable by element TAG rather than by class, and an owner nudge that
stacks alongside the existing one instead of merging with it.

**The absent-not-zeroed rule is the whole point of D-20, and it has a precise implementation.** Build
the response with the open tier assigned, then assign the restricted key ONLY inside the granted
branch. Never assign it from a conditional expression, never assign null, never assign an empty
object — serialisation omits a key that was never assigned, and that structural omission is what makes
the absence provable by stringifying the response and searching for the key name. A masked row still
discloses that decisions exist; a zero is itself information. Phase 4 proved this rule in UAT by
confirming uncleared areas were absent from raw markup rather than merely displaying zero, and this
plan's tests assert the same property at both the JSON and the DOM level.

**The tag-level distinction is a deliberate countermeasure, not a style choice.** The open tier is a
`div` and the restricted tier is a `section`. A stray class typo can survive undetected; a missing
element tag cannot. A raw-markup query for the restricted element returns zero for an uncleared caller
and exactly one for a cleared one, with no false positives from CSS. This is the same class of
countermeasure as the vacant-occupant element choice in Plan 01, and it exists because a Phase-5
regression that broke every card's interaction stayed invisible to a fully green test suite.

**The summary route must write no audit row.** Plan 05's register audit fires on every successful read
by decision — no session dedupe — and the deal home is the most frequently loaded surface in the app.
Wiring the read audit into anything the deal home calls would turn the compliance record into noise
within a day. Plan 05 already asserts this boundary in advance; this plan asserts it again from the
other side.

**Planner discretion recorded (06-RESEARCH.md Open Question 2):** the route mirrors the diligence
summary's structure — filter and derive once, then compute several named tallies from that single
pass — rather than issuing a narrowed query per number. It keeps the two rollup routes shaped alike
and leaves room for Plan 08's demo seed and any Phase-7 consumer to read more facets from the same
pass.

Canon-referral note (prohibition probe): the bespoke prohibitions for this capability are authored on
Plans 04 and 05, where the determinations are actually recorded; this plan re-enforces the privacy one
by construction, because the rollup returns counts and never names an individual.
</objective>
