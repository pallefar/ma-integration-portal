<objective>
Deliver ORG-01's spine end-to-end and prove the phase's single highest-leak-risk control on one real
path: a position is a first-class deal-scoped record (D-05) carrying a `current`/`target` state
discriminator (D-06), the current state is open to every deal member while the target state sits
behind the existing `hr` DD-area grant (D-01, D-02, D-07), and both are reachable from a new
`public/org.html` workspace page that gets no `pageAccess` entry (D-12, IN-02 precedent).

This is the phase's tracer plan. Task 1 wires ONE path — collection registry, SQL schema, zod
validator, server route with the clearance gate, page shell, tree card render, end-to-end test —
before any horizontal expansion happens. Tasks 2 and 3 harden that path's graph integrity and prove
its read boundary from four identities.

Purpose: prove the clearance-keyed-on-`state` architecture on one path before seven more plans build
decisions, a flight-risk register, a RAID outbound filter and a deal-home rollup on top of it.
Output: a working org workspace page backed by a registered collection trio and two new test files.

**Identity model (assumption-delta resolution, surfaced rather than assumed).** D-06 turns one
organisation into two — a singular-to-plural transition that needs an explicit identity rule. Locked
here: a position's identity is its `newId('pos')` id, and `state` is a **discriminator on one
record**, not a link between two. A current-state position and its target-state counterpart are
SEPARATE records with different ids and no cross-state identity field. Two consequences the plan
enforces rather than leaves to inference: (1) `reportsToId` may only reference a position in the same
`state`, refused server-side; (2) populating the target design copies rows into new ids (Plan 02's
copy action), it never re-points existing ones.

Canon-referral note (prohibition probe): XSS/injection on the new free-text `title` and `level`
fields, prototype pollution on the JSON write path, and MNPI data-retention after deal close are all
canon — covered by the existing zod pipeline, VAL-02's write-time sanitization, the app-wide
`textContent` render discipline and `/gsd-secure-phase`. Not minted as bespoke prohibitions here.

Planner discretion exercised and recorded (all delegated by 06-CONTEXT.md §Claude's Discretion):
- **Field set:** exactly `{id, title, level, reportsToId, employeeId, state, createdAt}`. No FTE, no
  location, no area/workstream tag — the tree (Plan 02) and the rollup (Plan 07) need none of them,
  and D-05 warns against speculative fields.
- **Three collections, not fewer:** `orgPositions`, `orgDecisions`, `orgFlightRisks`. A position, an
  append-only decision entry and a person-scoped risk entry have three different lifecycles and
  three different clearance stories; collapsing them would put an append-only log and a mutable row
  in one table.
- All three are registered in Task 1 even though only `orgPositions` is used here, so that
  `db/collections.js` and `db/schema.sql` are touched exactly once in this phase and later plans
  never re-open a file whose length assertion throws on load if it disagrees.
</objective>
