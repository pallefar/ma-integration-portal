<objective>
Deliver D-09 and D-10: populate a real deal's organisation without a parallel spreadsheet. A pasted
CSV or JSON block of `title, level, reportsTo, name, email` rows becomes positions plus linked
`employees` rows in one action, and deleting an employee who occupies a position is refused rather
than silently orphaning it.

Purpose: PROJECT.md's core value is explicitly "without keeping a parallel spreadsheet", and a
150-person target org is unworkable through the manual add form the tracer built. This is also the
only path that gives a real deal an `employees` roster at all — that collection is deliberately absent
from `DEAL_SEED_COLLECTIONS`, so a new deal starts with zero people.
Output: a bulk import route with an all-or-nothing contract, a two-step paste-and-preview importer,
and the first guard code `DELETE /api/employees/:id` has ever carried.

**Planner resolution of the one `⚠ unresolved` UI consideration.** 06-UI-SPEC.md's
`partial | paste-importer` row is the phase's single unresolved consideration: mixed valid/invalid
rows in one paste — reject wholesale, or import the good rows and report the bad. 06-CONTEXT.md
delegated it and the UI-SPEC re-confirmed it as still delegated. **Resolved here as all-or-nothing.**
Rationale: an org chart is a graph, not a list. Importing the good rows while dropping the bad ones
silently drops parents, so every child of a dropped row re-roots at the top level and the resulting
tree looks complete while being structurally wrong — a failure an operator cannot see by looking at
it. The rejected alternative (import-good-and-report-bad) is friendlier for a flat roster import and
is exactly wrong for a hierarchy. Recorded as an explicit assumption, not a silent choice.

**Planner resolution of an internal UI-SPEC inconsistency, surfaced.** §Copywriting Contract carries a
destructive-confirmation string for "delete employee linked to a position" reading "The position they
occupy will become vacant", while §Surface Contract 4's orphan-guard paragraph states the delete is
**refused**. These cannot both ship. Resolved toward **refusal** — it is the later, more specific
statement, it is what 06-RESEARCH.md read the UI-SPEC as having decided, and it fails closed on a
governance record. The confirm string is therefore not used for this case; the server's 400 message is
what the operator sees.

**Planner discretion recorded (delegated by 06-CONTEXT.md §Claude's Discretion — import
column-mapping tolerance):** header matching lowercases, trims and strips spaces and underscores, so
`Reports To`, `reports_to` and `reportsto` all resolve to the same column, and `manager` is accepted as
an alias. `reportsTo` resolves by TITLE — first against the other rows in the same paste, then against
existing positions in the requested state. A duplicate title inside one paste is refused, because
title-based parent resolution is undecidable when two rows share a title.

Canon-referral note (prohibition probe): prototype pollution on a parsed-JSON paste, injection through
free-text `title`/`level`/`name`, and PII-retention obligations on an imported roster are all canon —
covered by the zod pipeline, VAL-02's write-time sanitization, the `textContent` render discipline and
`/gsd-secure-phase`. Not minted as bespoke prohibitions here.
</objective>
