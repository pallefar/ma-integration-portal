<objective>
Execute D-07 and D-11: replace the five-value execution-status vocabulary with the four SYN-03
confidence stages (idea, validated, committed, captured) as a hard cutover with no compatibility
shim, in all three independent copies plus both committed databases and their i18n singletons.

vocabulary, so it must be settled — and settled once — before they are built.

partial edit impossible to ship.

`05-CONTEXT.md`: reverting requires a data migration of every stored initiative back to the

take only while `data/deals/` is empty (D-11's own stated premise) — which is why Task 2 carries a
precondition asserting that emptiness still holds at execution time.

`db/store.js:171-176` documents that the live app never opens it since the Phase 3 cutover. It is
migrated anyway because D-11's own text names it in the migration surface; skipping it would leave a
git-committed artifact holding a stale vocabulary, not break the running app.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `POST /api/synergies` | An untrusted body may carry an arbitrary `stage` string |
| Operator shell → committed `.db` files | The migration script writes directly to git-tracked SQLite files outside the request path, bypassing every runtime gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Tampering | `SynergyUpsertSchema` stage enum | high | mitigate | `z.enum(SYN_STAGES)` refuses any value outside the four, with no coercion branch in the handler — a retired or invented stage cannot enter storage, so the stage counts Phase 7's RPT-03 reads cannot be inflated by an out-of-vocabulary write |
| T-05-08 | Tampering | the three independent vocabulary copies | high | mitigate | Cross-file anti-drift test asserting all three arrays are deeply equal; a one-copy-behind edit turns the suite red rather than shipping a client that offers a transition the server refuses |
| T-05-09 | Tampering | `scripts/migrate-synergy-stages.js` | medium | mitigate | Operator-run script, not reachable from any route; idempotent by construction; asserted against a temp database in the test suite before it is run against a committed file; clean-tree precondition makes its diff attributable |
| T-05-10 | Repudiation | migration write invisible in git | high | mitigate | `wal_checkpoint(TRUNCATE)` before close plus an explicit `git diff --stat` acceptance criterion on both files — a migration that appears to succeed but leaves the tracked file byte-unchanged is treated as a failure, not a pass |
