<objective>
Build the substrate the steering-committee pack rests on: a way to turn drawn pages into a real PDF
file, in a vanilla no-build-step CommonJS codebase, with zero new npm dependencies, that renders all
four shipped languages correctly on Windows, macOS and Linux.

07-RESEARCH.md settled the mechanism decision by live verification against the actual vendored
binary and it is not to be re-derived: the canvas binding has NO PDF-writing surface at all, and a
vector-text PDF using the standard fourteen fonts cannot render Czech Latin Extended-A or Chinese
glyphs without a font-embedding subsystem. The path is therefore raster pages, deflated with the
standard library, wrapped in a hand-written minimal PDF 1.4 container — with the genuinely hard part,
glyph coverage, delegated to the canvas the repository already trusts.

This plan runs after the tracer only so the phase's export spine is proven first; it shares no files
with Plan 07-02 and executes alongside it.

Purpose: de-risk the phase's single largest unknown before any pack layout code is written.
Output: a vendored font with provenance, a direct dependency declaration, lib/reportPdf.js, and a
test that fails loudly if Chinese ever renders as empty boxes.
</objective>

    mid-string for mixed content such as a Latin codename beside a Chinese section header. The research

    SHA-256 checksum, and the licence identifier. Verify the file really is a font (its leading magic

    present and non-empty. This is a binary asset entering the repository, so the npm legitimacy gate
    does not apply, but the provenance discipline does. If the chosen family's full CJK coverage
    pushes the file past roughly ten megabytes, prefer a subset or a lighter static release and record

    exactly as the database driver and the validation library are pinned. Today it arrives only
    through the PDF-text-extraction package's optional dependency chain, so a future upgrade of that

<task type="auto">
  <name>Task 2: The minimal PDF 1.4 writer</name>
  <files>lib/reportPdf.js, test/reports-pdf.test.js</files>
  <action>
    Create lib/reportPdf.js as CommonJS, following lib/sanitizeHtml.js's module shape, exporting
    renderPageToRgbStream, buildPdf and the registered font family name constant.

    At module load, register the vendored font file from Task 1 under an explicit family name using the
    canvas binding's font registration call, resolving the path relative to the module's own directory
    so it works from any working directory and inside the release bundles. Register once at load, never
    per request. If registration fails, log via console.error with the security-and-diagnostics prefix
    convention and rethrow — a pack silently rendered in a fallback font is worse than a pack that
    fails to generate, because the failure would only be visible to a reader of Chinese.

    renderPageToRgbStream(drawFn, cssWidth, cssHeight, scale) creates a canvas at the CSS size times
    the scale, fills it opaque white, scales the drawing context so the callback can work in CSS-pixel
    coordinates matching 07-UI-SPEC.md §5's page geometry, sets the default font specification to the
    registered family, invokes the callback, then reads the raw pixel bytes, drops the alpha byte from
    each pixel to produce a three-channel buffer, and returns the pixel dimensions together with the
    deflated buffer produced by Node's built-in compression module. No image re-encoding step: the
    bytes go straight from the canvas to the PDF stream.

    buildPdf(pages) takes the array those render calls produced and returns a Buffer holding a complete
    PDF 1.4 file: the version header with the binary marker comment, a catalog object, a page-tree
    object listing every page, and per page an image object of the device-RGB deflate-filtered kind
    carrying the page's pixel stream, a content-stream object placing that image to fill the page with
    the transform and draw operators, and a page object declaring its media box in points and naming
    both. Then the cross-reference table with one entry per indirect object at its true byte offset,
    and the trailer naming the catalog as the document root, the total object count, the byte offset of
    the cross-reference table and the end-of-file marker.

    The critical correctness property is that every cross-reference offset is the real byte position of
    its object in the assembled buffer. Build the body incrementally, recording each object's offset as
    it is appended, rather than computing offsets after the fact from string lengths — a mixed
    binary-and-text buffer makes character-length arithmetic wrong in exactly the cases that matter.

    Expose the page count to callers before bytes are emitted: buildPdf must accept a fully-materialised
    array of already-rendered pages, so the caller can complete a measure pass, learn the total page
    count, and only then render each page with its correct page-of-total footer. Do not offer a
    streaming or incremental page-append interface — 07-RESEARCH.md Pitfall 5 and 07-UI-SPEC.md §5 both
    record that the every-page footer contract is infeasible with a naive single-pass writer, and an
    interface that permits it invites the bug.

    Extend test/reports-pdf.test.js: build a one-page and a three-page document; assert the buffer
    begins with the version header and ends with the end-of-file marker; assert the count of page
    objects equals the requested page count; parse the cross-reference table, follow every offset into
    the buffer, and assert each lands on a matching object header; assert the deflated stream round-trips
    back to the exact pixel byte length implied by the page dimensions; and assert a zero-page call is
    rejected with a clear error rather than producing an unopenable file.
  </action>
  <verify>
    <automated>node --test test/reports-pdf.test.js</automated>
  </verify>
  <done>
    lib/reportPdf.js turns drawn canvases into a valid multi-page PDF buffer with resolvable
    cross-reference offsets, using zero new npm dependencies, and its interface makes the two-pass
    page-of-total layout the only way to use it.
  </done>
