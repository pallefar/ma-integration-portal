<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ma-portal.db (mixed store) → three separated stores | The moment demo and control data stop sharing a file; a misrouted row lands permanently on the wrong side |
| demo.db (template source) → deals/<id>.db | Rows crossing here become part of a real acquisition workspace; a demo row that crosses is fabricated data inside an MNPI store |
| committed files (control.db, demo.db) → git remote | Anything written into these two files is published to every clone and every release bundle |
| caller-supplied dealId → filesystem path | An identifier from an API request eventually reaches a path join |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Tampering (silent data loss on a one-way migration) | runSplit / verifySplit | high | mitigate | Build every output at a temp path and rename only after a `--verify` union-parity gate over the three outputs versus the source is green; the gate fails on both drops and duplications; asserted by the corrupted-output case in test/db-split-migration.test.js |
| T-03-06 | Information Disclosure (credential committed to git) | settings.geminiApiKey / databaseConfig.connectionDetails | high | mitigate | SECRET_SETTINGS_FIELDS are lifted out of the demo `settings` singleton into runtime.db's `secretSettings`, and runtime.db is gitignored + zip-excluded by Plan 03-01; asserted by case (e) of test/db-split-migration.test.js |
| T-03-07 | Information Disclosure (fabricated demo rows inside an MNPI workspace) | createDealDatabase | high | mitigate | Allowlist-direction copy of exactly three template collections + i18n + a fresh settings singleton; every other collection proven empty across the full inventory by test/deal-seed.test.js (D-06) |
