<objective>
Land the fail-closed authentication spine end-to-end: promote the existing opt-in `PORTAL_AUTH` login to mandatory-by-default, replace the stateless HMAC cookie with an opaque token backed by a revocable SQLite `sessions` table, and consolidate the two overlapping `/api` gate middlewares into ONE gate that resolves a server-side identity (`req.portalUser`) on every request. Implements D-01, D-02, D-03, D-06, D-07, D-08.

Purpose: This is the architectural inversion the whole milestone's MNPI compliance rests on — an unauthorized read becomes impossible by default, not opt-in. Every later plan and phase builds on the `req.portalUser` identity and the `isOpenMode(req)` seam this plan establishes.
Output: A consolidated fail-closed gate, a dedicated sessions table + `db/sessions.js`, the `server.js` requireable-module refactor, and two node:test proofs (route-inventory 401 sweep for AUTH-01; session lifecycle for AUTH-03/AUTH-04).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api gate | Untrusted cookie/token crosses into the app; the gate is the sole authentication boundary (no client-side trust) |
| app → sessions table (SQLite file) | The .db file is an exfiltration target (backup, stolen laptop); what is at rest must not be directly replayable |
| env (DEMO_OPEN) → gate | An operator/launcher misconfiguration can flip fail-closed to open |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing / Elevation | consolidated /api gate | high | mitigate | Fail-closed default (D-01): no valid session ⇒ 401 on every /api route incl. reads; proven by test/auth-route-inventory.test.js live route-inventory sweep (AUTH-01) |
| T-02-02 | Information Disclosure | sessions table at rest | high | mitigate | Store SHA-256 `token_hash` only, never the raw token (D-06); a leaked .db dump cannot replay live sessions; asserted in session-lifecycle.test.js |
| T-02-03 | Spoofing (session fixation / non-revocation) | session lifecycle | high | mitigate | Server-side revocable rows: logout deletes the row, admin revoke-all for a user, absolute 12h expiry with lazy-on-read enforcement (D-07); asserted in session-lifecycle.test.js |
| T-02-04 | Tampering (CSRF on cookie-authorized writes) | login cookie + gate | medium | mitigate | `SameSite=Strict` (D-08) + HttpOnly + Secure-when-HSTS on the ma_session cookie; app sets no CORS headers and accepts JSON-only bodies (research-verified) — no new CSRF lib (V5 Sec-Fetch-Site hardening deferred to no-new-dep baseline) |
| T-02-05 | Information Disclosure (MNPI leak via accidental open mode) | isOpenMode seam | high | mitigate | DEMO_OPEN is an explicit env opt-in, default is fail-closed; `isOpenMode(req)` kept as a named seam so Phase 3 can AND it with req.isDemo so a real-deal DB is NEVER open (D-03) |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | This plan introduces NO new packages (Node crypto + already-committed better-sqlite3 only); Package Legitimacy Gate N/A per 02-RESEARCH.md |
</threat_model>
