<objective>
Add real role differentiation to writes and close the account-safety gaps: a single coarse `ROLE_WRITE_POLICY` capability check on the gate's write branch (D-04/D-05), an attributed break-glass identity for `X-Admin-Token` (D-11), a seeded `employee` account so the non-admin path is testable (D-12), self password-change plus a first-run admin-secret script (D-09/D-10). Depends on the consolidated gate + session identity from Plan 01.

Purpose: AUTH-02 is net-new — today any authenticated session can write to all 59 non-admin routes identically. This plan makes write authorization real without hand-annotating ~90 endpoints, and ensures real-deal mode never ships on the publicly-known demo password.
Output: A path-prefix role policy wired into the gate, request-aware admin guards, the self password-change endpoint, the set-admin-password CLI, a seeded employee account, and the AUTH-02/AUTH-04 role-enforcement test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session role → write authorization | The caller's role (from the server-side session) decides whether a write proceeds |
| X-Admin-Token → identity | A shared secret must resolve to an attributable identity, not an anonymous bypass |
| operator → admin credential | Real-deal must not run on the publicly-known demo password |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Elevation of Privilege | gate write branch / ROLE_WRITE_POLICY | high | mitigate | Role read only from req.portalUser.role (server session), checked against a coarse capability map on every write; hrbp/pmo→403 on admin writes, employee→403 on non-self-service writes (AUTH-02); proven by test/role-enforcement.test.js |
| T-02-07 | Elevation / silent-open on new endpoints | default-allow policy | medium | mitigate | Unlisted write prefixes default to admin/hrbp/pmo only — never silently open to employee; new milestone endpoints are safe-by-default at the higher tier |
| T-02-08 | Repudiation (unattributed break-glass write) | X-Admin-Token path | medium | mitigate | D-11: admin-token requests resolve to a stable `{username:'admin-token', role:'admin'}` identity so Phase 3 audit (AUD-01) can attribute them |
| T-02-09 | Spoofing (credential exposure) | admin account credential | high | mitigate | First-run set-admin-password (D-09) + loud warning when the demo password persists in a non-demo deployment (D-10); scrypt hashing preserved unchanged |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages introduced (Node crypto + better-sqlite3 only); Package Legitimacy Gate N/A |
