Do not re-derive these. Each was independently re-verified against current `main` while writing this plan.

**F1 — stored XSS sink (proven live in headless Chrome by the reviewer).**
`public/js/leaders.js` lines 110-130 build a template literal assigned to `row.innerHTML` interpolating the employee name indexed at zero (line 113), the employee name (line 116), the employee role and the points figure (line 117) — all unescaped. The name is stored via `POST /api/employees` and is not escaped on write. An `escapeHtml` helper already exists in the same file at line 268 and is already used at line 219; it is simply not applied here.

**F2 — the shared regex sanitizer is bypassable (proven live via `POST /api/i18n`, fired on `integration-excellence.html`).**
Every handler-strip rule requires a **whitespace** character before the handler name. The forward slash is also a valid HTML attribute separator, so the img-slash-onerror shape passes straight through.

**F2-EXTRA — a THIRD copy exists that the reviews did not name, and it is the most important one.**
A repo-wide grep for the handler token across `public/js`, `lib`, `validators` and `server.js` returns exactly nine lines across **three** files, not two:
- `public/js/page-layout.js` lines 16-18 (client render-time, `sanitize`)
- `public/js/transitions.js` lines 3333-3335 (client render-time, `stripDangerousHtml`)
- `lib/sanitizeHtml.js` lines 47-49 (**server-side, write-time**, `sanitizeHtml`)

`lib/sanitizeHtml.js` is a deliberate port of the `page-layout.js` regex (its own header says so) and is what `validators/index.js`'s `htmlField()` and `applySanitization()` run on every write to a tagged field. It carries the identical bypass. Fixing only the two client copies would leave the payload **stored intact at rest** and neutralized only at render — the exact defence-in-depth inversion `lib/sanitizeHtml.js` was created to prevent. This repo has a documented history of duplicated constants drifting (`RAID_LEVELS` and `SYN_STATUSES` are each triplicated and each carry an anti-drift test); this is the same class and gets the same treatment.

**F3 — hygiene.**
`public/sent_emails` is not in `.gitignore`, yet `server.js` line 1106 and line 1113 explicitly treat that directory as secret-bearing and exclude it from the admin download-zip export. `server.js` lines 4976-5008 write real outbound comms there at runtime.
