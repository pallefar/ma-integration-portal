<objective>
Make the M&A portal boot on any platform again by removing @napi-rs/canvas from server.js's module-load path, and degrade only the one route that needs it.

Proven in Docker during milestone-close Linux boot verification: `server.js:59` does a top-level `const reportPack = require('./lib/reportPack');`, and both `lib/reportPack.js` and its `lib/reportPdf.js` dependency require `@napi-rs/canvas` at THEIR module load. The committed `node_modules` tree vendors skia bindings for four platforms only (darwin-arm64, darwin-x64, linux-x64-gnu, win32-x64-msvc). On linux-arm64 the portal dies at boot with `Cannot find module './skia.linux-arm64-gnu.node'` — a Phase-7 regression, since before Phase 7 canvas was an unused optional dependency and those hosts booted fine.

Purpose: the zero-install bundle's whole promise is `node server.js` on whatever host the user has. A missing PDF feature is a degradation; a portal that will not start is an outage.
Output: server.js acquires the pack module lazily inside the route, with a 503 refusal when the host cannot load it; four new tests lock the invariant in place.
</objective>
